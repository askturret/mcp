Serve your existing OpenAPI spec as an MCP server.

AskTurret MCP reads the spec you already have and serves it over the Model Context Protocol. No code generation, and no second copy of your API to keep in step with the first.

Quick start

Mount it into an Express app you already run. The MCP layer is the single app.use line. 

npm install express @askturret/mcp-adapters-express
import express from 'express';
import { mcpFromOpenApi } from '@askturret/mcp-adapters-express';

const port = Number(process.env.PORT ?? 7078);
const app = express();
app.use('/mcp', mcpFromOpenApi('./petstore.yaml'));
node server.mjs

Your API now exposes tools over MCP. Ask it what it has:

curl -X POST http://localhost:7078/mcp \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

Abridged from the runnable walkthrough, which includes the sample spec, the full server.mjs with its port-collision handling, and the expected output at every step. Every command above is asserted to appear verbatim in that walkthrough, so the two cannot drift apart — read the full quick start.

Three ways to run it

Into an Express app

Mount as middleware on a route you choose. Express 4 and Express 5 are both supported, and CI runs a matrix leg against each.

Into a Fastify app

The same model, registered as a Fastify plugin, for services already built on that stack.

As a standalone gateway

Run it in front of an API you would rather not modify at all. Nothing needs to change on the other side.

Check the supply chain yourself

Every published package carries SLSA build provenance, and every tarball ships LICENSE and NOTICE inside it. Neither is a claim you have to take on trust — ask the registry: 

npm view @askturret/mcp-core@0.2.0 dist.attestations

Provenance ties a published tarball to the workflow run and the commit that built it, so “this came from that source” is something the registry answers rather than something this page asserts.

Where the project actually is

Honest version, because overselling a young project costs exactly the readers worth having:

  • 0.2.0, published 2026-09-11 — nine public packages under the @askturret scope.
  • Pre-1.0. The compatibility policy is written and published, but it is dormant below 1.0.0 — under semver, 0.x carries no compatibility guarantee.
  • 2,055 tests across 12 suites, run on every pull request.
  • Apache-2.0, with the licence and NOTICE inside every published tarball.
  • Node 20 or newer.

There is no adoption story here yet, and this page will not invent one. What the repository can evidence is the list above; anything beyond it would be decoration.
